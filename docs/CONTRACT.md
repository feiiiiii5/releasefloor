# ReleaseFloor 0.1 contract

ReleaseFloor reads the publisher's own release artifacts. It never executes them. Input and member hashes describe bytes, not authenticity, safety or complete runtime compatibility.

`floor.Inspect(data []byte, member string) ([]Binary, error)` reads original ELF and Mach-O metadata, including universal slices. ELF platform is `elf` (the file format alone does not prove Linux); Mach-O platform is its recorded build platform, such as `macos`. Architectures use `amd64`, `arm64`, `386`, `arm`, with a suffix for a meaningful Mach-O CPU subtype. Each returned binary has its original member path and byte hash. Non-runtime content returns `ErrNotBinary`; recognizable unsupported binary formats return `ErrUnsupported`; malformed supported formats return an error. Unknown required metadata stays visible in `Binary.Unknown`. No fabricated zero-version floor.

`floor.Scan(path string, limits Limits) (Inventory, error)` accepts a raw binary, ZIP or tar.gz (also `.tgz`). It inspects regular members by magic, not filename or executable bits. No extraction, symlink following, recursion into nested archives or network access. Known executable formats outside scope and nested archives produce explicit coverage issues. Non-binary documentation is counted as ignored. ZIP CRC errors, duplicates, encrypted entries, path traversal, excessive members/decompression/input size and malformed archives fail. Symlinks are reported as not followed. At least one supported runtime binary is required. Inventory `complete` is false on error-level issues or unknown binary metadata. Default limits are 128 MiB input, 64 MiB/member, 256 MiB total regular bytes and 4096 members. `StripComponents` is explicit; do not guess version-prefix mappings. Duplicate normalized member/platform/arch identities fail. Sort records for reproducible output.

`scan ARTIFACT` emits inventory JSON or a human summary. `compare OLD NEW` scans both and aligns exact normalized member/platform/architecture identities; added binaries are informative, removed binaries and increased numeric floors/minimum OS block the gate. Added direct dependencies request review. Unknown or incomplete coverage blocks. Raw single-binary inputs use the stable member name `binary` so renaming the outer artifact does not break comparison. Archive member paths remain significant.

`check --policy POLICY ARTIFACT...` applies explicit per-platform/architecture maximums to a release matrix. Every binary must match at least one rule; no silent exemption for an unexpected architecture. Every rule with both literal platform and architecture requires at least one binary in the matrix; wildcard rules do not promise specific targets. Rules do not enumerate every required member: compare with a previous artifact to detect member removals. In a complete inspection, a version family with no recorded requirement satisfies its ceiling (a static binary need not import GLIBC). Unknown/missing required metadata still blocks. Supported policy platforms are `elf`, `macos` or `*`; floor families are `GLIBC`, `GLIBCXX`, `CXXABI`; macOS uses `max_os`. JSON policy schema is `releasefloor.policy.v1`. Empty rules, unknown properties, duplicate rule identities and invalid numeric versions are errors. At least one artifact is required. These checks do not certify runtime support.

Exit status: 0 means all implemented checks completed with no blocking finding; 1 means a complete report contains blocking findings/unknown coverage; 2 means invalid input, policy, invocation or I/O failure. JSON reports use `releasefloor.report.v1`. Reports include artifact basenames, archive member names and metadata, not local absolute paths. Output is written only to stdout unless `--output` explicitly names a new file; never overwrite existing files or inputs. HTML reports escape imported names and contain no remote assets or scripts.

Numeric version comparison uses integer components, padding with zeros (`2.10 > 2.9`, `12 = 12.0`). Original version nodes and provider names remain evidence. Non-numeric ABI nodes are not silently mapped to a minimum version. ELF big-endian variants use a `-be` architecture suffix, so they cannot silently match little-endian builds. For Mach-O, an existing provider's increased recorded compatibility version or a weak import becoming required blocks comparison for review; this is not proof that the new library ABI is incompatible. Policy field spelling is case-sensitive. Dynamic loading, transitive libraries, CPU instructions, kernel requirements and runtime behavior remain outside this preflight. Keep real target-system smoke tests.
